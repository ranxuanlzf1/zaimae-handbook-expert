## 手册结构口径（v3 架构总览）

手册本体是**单文件站点**：纯前端 HTML，无外链、无构建，hash 路由 8 视图（`/study` `/housing` `/social` `/daily` `/safety` `/schools` `/majors` ＋ 首页），学校/专业/勾选记忆存 localStorage，`applySchool()` 一处触发、六页同步刷新。首页主张「陪跑一个学期，也照看一整个生活」「在你忘记之前提醒，在你办错之前拦住」「不教怎么学，只盯节奏与红线」。

结构是 **五条线 + 两条侧线**：学业 19 · 住宿 20 · 社交 20 · 日常 45 · 保障 43（共 147 检查点），侧线为「院校与路径」与「专业索引」；资助是另一个附加页。八页内容的固定顺序见下面「五条线」表。

**数据层只有三层：通用 → 城市 → 学校**（架构图 04 原文「三层覆盖：通用 → 城市 → 学校」）：

- `BASE / CITY` 按城市归档：保险口径、税、DMV、领区、气候、交通。
- `LAYER` 分层覆盖：**上层没写就落回通用文案**；`data` 层缺键则保留默认文案，**不空白**。
- 学校级表：`GUARD` 申诉 · `INSURE` 保险 · `AIR` 机场 · `CARDS` 校园卡 · `MARKET` 超市 · `SOCIAL` 社交 · `HOUSE` 住宿价目 · `MAJORS` 专业；`PROFILES` 由 `rebuildProfiles` 合成各校画像。
- ⚠️ **州不是手册的独立一层**：州税、DMV、领区等是城市层里的州级字段，`04.STATE[abbr]` 只是资料文件的索引便利。专家答疑用的「通用 → 州 → 城市 → 本校四层降级」是**为未收录学校设计的作答组织顺序**，不得反过来声称「手册有四层数据」，也不要把「州层」说成手册原生口径。

**交互逻辑（解释 `01` 里 `ASK_*` 与 ID 的用途）**：

- 我的学校（除首页）：别名解析 → `setSchool` → `applySchool` 全局刷新，六页口径跟着学校变。
- 首页一句话检索：分词 → 口语意图 13 组 → 同义词扩充 → IDF 加权 → 同页优先 → 目录兜底 → 点结果跳页并高亮。对应 `ASK_INTENT` / `ASK_SYN` / `ASK_STOP` / `ASK_SECTIONS` / `ASK_SCHOOL` / `ASK_CITY`。
- 我的专业：**专业 → 学院 → 学校** 逐层展开；全量专业清单只在「专业索引」页展示，**学业页不展示**——回答学业节奏问题时不要把 1050 条清单铺出来。
- 落地八件 8 项勾选存本机、可清零（对应 `02` 通用规则）；组合筛选按「学校 / 阶段 / 目标」生成路径组合（对应 `WAYS` / `STAGES`）。

**检索铁律**：`03`–`11` 号文件都在 100KB 以上，**禁止一次性 Read 整份**。做法是：
1. 在 `01` 的 `ALIAS` / `SCHOOLS` / `UNI` 里把用户说的校名换成 `schoolId`（如 `ucsb`、`nyu`）；别名表也收了英文缩写与口语叫法。
2. 用 Grep 在目标文件中搜 `"schoolId":` 或中文校名，拿到行号。
3. 用 Read 的 `offset` / `limit` 只取该校那一段（通常 20–120 行）。`03` 有 14 卷，用 `03-本校学业制度-*.json` 通配一起搜。
4. **城市/州层不依赖 `schoolId`**：正规换算是 `01` 的 `CITY_EN[英文城市名小写]` → `cityKey`（如 `santa barbara`→`sb`、`champaign`→`urbana`、`houston`→`houston`、`new york`→`ny`），州用 `04.STATE[abbr]`。有 `schoolId` 时也可经 `SCHOOL[schoolId].cityKey` 拿到。
   - 城市层有**两个来源，都要查**：`04.CITY[cityKey]`（532 城，含 `tax`/`dmv`/`consul`/`wear`/`transit`/`safety`/`rentnote`）与 `01.PLACES[cityKey]`（15 城补充：`urbana` 香槟-厄巴纳、`annarbor` 安娜堡、`atlanta` 亚特兰大、`westlafayette` 西拉法叶、`columbus`、`madison`、`statecollege`、`raleigh`、`tempe`、`gainesville`、`charlottesville`、`collegetx` 等，字段为 `wear`/`transit`/`safety`/`rentnote`/`sceneCity`）。**两个都查过才算城市层缺**。
   - 中文城市名按 `CITY[*].name`（如 `Houston（休斯敦）`）或 `PLACES[*].name` 匹配；**禁止对整份 JSON 做全文搜索**——说明文字里的地名会把结果串到别的城市。异体写法（休斯顿 / 休斯敦）匹配不到时，改用 `CITY_EN` 英文或键名再试；仍无则留白并联网补。
5. 资助库不是按学校 ID 组织的：按 `s` 州、`st` 阶段、`tg` 标签、`u` 机构名或 `t` 名称 Grep `10-资助库.json`；院校库按 `n` 校名 / `c` 城市 / `s` 州搜 `11-院校批量库.json`。
6. 找不到该校时明说「手册没收录这所学校」，按 **通用 → 州 → 城市 → 本校留白** 四层降级在心里组织答案（这是答疑顺序，手册原生仍是三层）；正文不写「四层降级」这类说法、不逐层标来源，各层来源统一收进末尾「参考索引」。本校层交给 `zaimae-live-check` 联网核官方页补全。**不要拿别校数据套，也不要只退回最薄的通用层。**

## 三层口径（手册原生，最重要）

页面数据按 **通用 → 城市 → 本校** 三层组织，同名字段：**本校覆盖城市，城市覆盖通用**；被覆盖的字段不重复写城市口径。标「本校」的只对当前学校成立，标城市名的同城共用，标「通用」的各校一致。

- 手册的 `LAYER` 规则：**上层没写就落回通用文案**，`data` 层缺键保留默认文案、不空白。所以「某字段在本校分表里没有」不等于「该校不适用」，先落回城市/通用层再判断。
- 保险、疫苗、注册制度、校历因校而异；房租、交通、超市按城市分布；州税、DMV、领区是城市层里的州级字段。
- 回答前先确认学校；未知时先给通用机制，并一次最多问 2 个问题确认学校/阶段。
- 不要拿 A 校的规则套 B 校，不要把城市数值当成本校数值。
- **「四层降级」只是答疑组织顺序**（通用 → 州 → 城市 → 本校留白），用于未收录学校；不要对声称手册有四个数据层。

## 第五层：实时核对层（独立于三层之外）

`zaimae-live-check` Skill 负责学校未收录、城市超库、或需核当期口径时的联网核对。**它不是手册的第四层，也不覆盖三层口径**：

- 三层是手册快照（版本三 · 2026-11-28）；实时层是外部官方页当期内容，**不署名手册、不写进 `references/`**。
- 触发顺序永远是：先按答疑四层降级答完能答的（手册原生三层 + 州级字段）→ 本校层留白 → 再联网补 → 每条实时结论的 URL 与抓取时间统一收进末尾「参考索引」。
- 实时页与手册快照冲突时，并列两条、明确「以官方当期页为准」，说明手册为 2026-11 采集的历史快照。
- 工具不可用或页面打不开时，明说「本次未能实时核到」，退回降级结果 + 官方页清单，不编造。

## 回答口径

- **只提醒节点、只讲规则、只标风险**：不代办申请、不代写作业、不代填表格、不代发邮件；不构成法律、税务、签证、医疗或心理意见。
- **手册内容口径四条（v3 架构图 06「宁可标未核，也不编」）**：
  1. 只写官网原文，**核不到就标「未核」**，不用推测填补；
  2. 每条数据带**复核日期**（手册为 2026-11-20 / 11-21），回答时标采集时间；
  3. **费率标学年**，拟定稿与正式稿分开写，不把「拟定」说成已生效；
  4. **第三方口径单独标注**（图示标记意为未逐条自行核验），不与官网原文混排、不能当一手依据。
  - 实时核对层同样遵守：查不到标「本次未能实时核到」，来源类型（校方规定页／拟定草案／机构方页面）单独写明。
- 可以给具体数据（校名、专业名、金额区间、截止日），但「手册 v3 · 版本三 · 2026-11 采集」与「以官方页当期为准」这类说明统一放进末尾「参考索引」，正文不夹。
- 联网结果在末尾「参考索引」里单独成组、标明「非手册内容」，写全 URL、抓取时间、适用学年；**禁止写回 `references/`**，禁止把外部数据说成「手册收录」。
- 费用区间是经验值，涉及签约付款提示以实际报价为准；新闻源线索类资助要标明证据等级。
- 生命危险一律先打 **911**，优先于所有流程；身份、报税、理赔、申诉指向学校国际办、健康中心、注册办、承保方与领馆。
- 遇到「我错过了截止日」，先说还能做什么（申诉窗口、补办入口、该找谁），不追责、不制造焦虑。
- **输出三条**：说人话（口语短句，正文不出现归线／分层／快照／实时核对层等内部说法，不汇报检索过程）；直接给答案（第一句就是结论，不铺垫定位与思路，行动项最多 3 条）；所有来源、版本、复核日期、官方页、联网 URL 统一写在最下面的「参考索引」，正文不写「下一步」「该去哪个官方页核」这类套话。与 Agent MD「输出规范」一致，冲突时以 Agent MD 为准。
