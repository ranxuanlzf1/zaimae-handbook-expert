## 从 GitHub 安装

**先记住一条**：`references/` 下 15 份资料是中文文件名。**不要用 Windows 资源管理器解压 zip**，会解成乱码、Skill 检索全部失效；请用 7-Zip / Bandizip，或 Python 的 `zipfile`。

**方式 A · 下载现成包（推荐）**

1. 到本仓库 Releases 下载最新版 `zaimae-v2-handbook-v1.2.0.zip`；也可以执行 `python tools/pack.py` 自行生成，产物在 `dist/`。
2. 用 7-Zip / Bandizip 解压，得到 `zaimae-v2-handbook/` 目录。
3. 把**整个目录**放进「我的专家」插件目录：
   - Windows：`C:\Users\<Windows用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\`
   - macOS / Linux：`~/.workbuddy/plugins/marketplaces/my-experts/plugins/`
4. 重启 WorkBuddy，在「专家 → 我的专家」里就能看到「道哥是留子」。

**方式 B · 从源码导入**

在仓库页点 **Code → 复制 URL**，然后：

```bash
git clone <刚才复制的仓库 URL>
cd zaimae-handbook-expert
python tools/pack.py          # 生成干净的 zip，排除 .git / LICENSE / tools
```

然后照方式 A 的第 2–4 步导入。clone 出来的目录名是仓库名，与 `plugin.json` 的 `name`（`zaimae-v2-handbook`）不一致，所以**别直接把仓库目录塞进 plugins**——用打包脚本生成标准目录名最省事。

**维护者 · 首次推送**

```bash
git remote add origin <刚才复制的仓库 URL>
git push -u origin main
```

GitHub 已停用账号密码登录，HTTPS 推送需 Personal Access Token，或先配置 SSH key。在 GitHub 新建仓库时不要勾选 Add a README / license / .gitignore，避免与本地首次提交冲突。

**方式 C · 发布到专家市场**

把 zip 上传到 [WorkBuddy 开放平台](https://open.workbuddy.cn/expert/publish?action=create&step=1)（≤ 20 MB），平台会自动解析 `plugin.json` 生成草稿。注意 `profession.zh` 在同一账号下须唯一。

> Windows 上想让终端正常显示中文文件名：`git config --global core.quotepath false`。

## 手册结构口径（v3 架构）

手册是**单文件站点**：纯前端 HTML、无外链无构建、hash 路由 8 视图、学校/专业/勾选记忆存 localStorage，`applySchool()` 一处触发六页同步刷新。首页主张「陪跑一个学期，也照看一整个生活」「在你忘记之前提醒，在你办错之前拦住」。结构是**五条线 + 两条侧线（院校与路径、专业索引）＋ 资助附加页**，共 147 个检查点。

- **数据层只有三层：通用 → 城市 → 学校**。`BASE/CITY` 按城市归档保险口径、税、DMV、领区、气候、交通；`LAYER` 上层没写就落回通用文案，`data` 层缺键保留默认文案、不空白；学校级表为 `GUARD`/`INSURE`/`AIR`/`CARDS`/`MARKET`/`SOCIAL`/`HOUSE`/`MAJORS`，`PROFILES` 合成学校画像。
- ⚠️ **州不是手册独立一层**：州税、DMV、领区属城市层里的州级字段，`04.STATE` 只是资料索引便利。专家的「通用 → 州 → 城市 → 本校四层降级」是**为未收录学校设计的作答顺序**，不是手册层数。
- **交互逻辑**：别名解析 → `setSchool` → `applySchool` 全局刷新；首页检索「分词 → 口语意图 13 组 → 同义词 → IDF 加权 → 同页优先 → 目录兜底 → 跳页高亮」；我的专业按「专业 → 学院 → 学校」逐层展开，全量清单只在专业索引页展示、学业页不展示；落地八件 8 项勾选存本机；组合筛选按学校/阶段/目标生成路径。
- **内容口径四条（宁可标未核，也不编）**：只写官网原文、核不到标「未核」；每条带复核日期（2026-11-20 / 11-21）；费率标学年、拟定与正式分开写；第三方口径单独标注、不与官网原文混排。实时核对层同样遵守。
- **质量与交付**：手册侧自检链 `check.py → full_check.py (ALL PASS / total 1050) → smoke.js → house_smoke.js`，改动前落 `_backup/` 快照，发布走 `deploy → release-get`。专家包侧对应「重新导出 → 重建 references → 重新打包」。

> 架构示意图标「11 校 / ≈300 KB / 8 视图 / 11 校画像」属早期或示意描述，本包以 2026-11-28 实际导出的 8.96MB HTML、607 条院校条目、594 索引为准（`ROUTES` 实际 9 条，含 `/aid`），回答规模时不引用示意图数字。导出的 43 个顶层变量中 40 个已拆进 `references/`；`LAYER`、`COMPOSE` 是空对象（运行时逻辑）、`SKEY` 是 localStorage 键名、`PROFILES` 由函数运行时合成，均不是可查资料文件。

|---|---|---|---|

| 日常 | 生活成本的一半，藏在细节里 | 45 | 落地第一周七天顺序＋八件勾选 → 吃（超市分级·营业·学生卡·距离）→ 穿 → 行（学生交通·首末班·机场）→ 用（手机·开户·通信）。**行在用之前** |

## 实时核对层（第五层）

**触发**：学校或城市不在库、问题涉及当期截止/金额/阈值、用户要官方链接或问「现在还这样吗」。纯通用机制问题不联网。

**流程**：先四层降级（通用 → 州 → 城市 → 本校留白；**作答顺序，手册原生三层**；城市层要同时查 `04.CITY` 与 `01.PLACES`）答完能答的 → 按主题找对应官方部门页 → `WebSearch` 限 `site:` 找入口 → `WebFetch` 打开原页核正文 → 学年与状态对齐、交叉验证 → 每条结论的来源收进末尾「参考索引」，正文只给答案。

**依据范围**：校方 `*.edu`（注册办、General Announcements、健康中心、ISSS、housing、financial aid）、政府 `*.gov`（IRS、USCIS、SSA、州 DMV / 税务）、中国驻美使领馆、机构官网。论坛、中介、个人博客、公众号、二手汇总最多算线索，不能当成规则或阈值。

**标注格式**：不再单独开「实时核对层」区块。所有联网结论在末尾「参考索引」里以「联网（非手册内容）」开头的短行给出：结论＋完整 URL＋来源类型＋抓取时间＋适用学年＋与手册快照的关系；手册来源另起一行，两类不混排。当期页与快照冲突时并列两条，明确以官方当期页为准；核不到标「未核」。

**两条硬约束**：查不到就明说「本次未能实时核到」并给官方页清单；**禁止把实时结果写回 `references/`**。要把新学校固化进手册，走「更新飞书手册 → 重新导出生成 references → 重新打包」的正规流程。

## 安装与打包

专家包位于 `$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/zaimae-v2-handbook`（默认 `~/.workbuddy/...`），已通过 `register_expert.py` 注册到 `marketplace.json`，在「我的专家」中可见。

```bash
python scripts/validate_expert.py <expert-dir>
python scripts/register_expert.py <expert-dir>
python scripts/package_expert.py <expert-dir> <output-dir>
```

修改 `plugin.json`、`agents/*.md` 或任一 `SKILL.md` 后需重新校验并注册；仅更新 `references/` 下的资料不需要重新注册，但要重新打包 ZIP。

**手册更新时怎么同步**：手册站改动 → 重新导出应用源码 → 跑数据导出与 references 生成脚本 → 比对关键计数（专业总数 1050、资助 303、院校条目 607、院校索引 594）→ 重新打包 ZIP。仅数据变化不用重新注册；实时核对层查到的新学校**不写进 references**，必须走手册侧更新才算固化。
